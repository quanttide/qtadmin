# 任务页设计

任务页承载「分配工作」：任务绑定角色槽位而非具体人，解决「谁来接」的归属问题。

## 定位

对齐洞察 review-path 第二步「责任划分」：任务分配时按任务类型绑定默认评审人，职责从分配时刻起就有明确归属，不回流创始人。

## 数据

Task 模型（`lib/models/task.dart`）：

| 字段 | 说明 |
|------|------|
| title | 任务标题 |
| type | 任务类型（常规 / 政策类 / 重大），决定评审人 |
| assignee | 执行人 |
| deadline | 截止日期 |
| deliverable | 交付物（执行契约） |
| reviewer | 评审人，默认取角色槽位 |
| status | 状态（待执行 / 待评审 / 已通过 / 已打回） |
| reviewNote | 评审意见（打回原因 / 通过备注） |

## 交互

- 列表：卡片展示任务信息与状态标签，待执行任务可「提交评审」，已打回任务可「重开」
- 新建：表单（标题、类型、执行人、截止日期、交付物），保存后自动绑定角色槽位评审人

## 状态流转

```
open（已分配）→ inReview（已提交）→ approved（已通过）
                              ↘ rejected（已打回）→ open（重开）
```
